# Requirements SINAU

Dokumen kebutuhan:
- PRODUCT-REQUIREMENTS.md — tujuan, persona, kebutuhan produk.
- MVP-SCOPE.md — batas implementasi tahap awal.
- REGISTRATION-AND-ONBOARDING-FLOW.md — alur pendaftaran yayasan dan sekolah/madrasah mandiri, data, membership, dan acceptance criteria.
- ROLES-AND-PERMISSIONS.md — peran dan batas akses.
- ACCEPTANCE-CRITERIA.md — kriteria penerimaan MVP.
- BUSINESS-PROCESS-MAP.md — process register end-to-end dan alur lintas domain.
- PLATFORM-TENANT-PROCESS-SPECIFICATIONS.md — BP-PLT-01—06: onboarding, unit, verification, subscription/entitlement, identity/access, dan lifecycle tenant/unit.
- ORGANIZATION-AND-STUDENT-PROCESS-SPECIFICATIONS.md — BP-ORG dan BP-STD; mencakup minimum lifecycle siswa MVP dan roadmap lifecycle lanjutan.
- ACADEMIC-ATTENDANCE-ASSESSMENT-PROCESS-SPECIFICATIONS.md — BP-ACA, BP-ATT, dan BP-ASM; memisahkan penilaian/presensi dasar MVP dari timetable, LMS, dan rapor formal post-MVP.
- ADMISSIONS-AND-HR-PROCESS-SPECIFICATIONS.md — BP-ADM (PPDB post-MVP) dan BP-HR (HR minimum MVP versus HRIS lanjutan), termasuk batas ownership profil pegawai dan assignment akademik.
- PROCESS-SPECIFICATION-CONSISTENCY-AUDIT.md — temuan audit AUD-01—09, status remediasi, dan keputusan yang masih menunggu product owner.
- MVP-SCOPE.md — sumber batas release MVP; status Proposed sampai disetujui product owner.

**Catatan:** spesifikasi proses adalah draft kebutuhan/alur, bukan module blueprint lengkap atau persetujuan implementasi. Lihat `../01-blueprint/BLUEPRINT-CATALOG.md` dan `../00-governance/PROJECT-PROGRESS.md` untuk status artefak serta release boundary.

Semua requirement harus memiliki ID, status, dan acceptance criteria. Perubahan scope mengikuti CHANGE-CONTROL.md.
